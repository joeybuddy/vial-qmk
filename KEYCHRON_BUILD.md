# Keychron Keyboards - Build and Release Process

This document describes the automated build and release process for Keychron wireless keyboards.

## Supported Keyboards

- **K2 Pro (ANSI RGB)** - 84-key layout with RGB matrix
- **K3 Pro (ANSI RGB)** - 84-key low-profile variant
- **Q8 Pro (ANSI Encoder)** - 69-key Alice layout with rotary encoder

## Automated Build Pipeline

The repository includes a GitHub Actions workflow (`.github/workflows/build-keychron.yml`) that automatically builds firmware for all supported keyboards.

### Trigger Conditions

The build pipeline runs automatically when:

1. **Push to `keychron` branch** - Builds and stores firmware in keyboard directories
2. **Tagged release (v*)** - Builds and creates a GitHub Release with downloadable firmware
3. **Pull requests** affecting `keyboards/keychron/**` - Validates changes don't break builds
4. **Manual trigger** - Can be run manually via GitHub Actions UI

### Build Matrix

The pipeline builds the following combinations:
- Each keyboard: k2_pro, k3_pro, q8_pro
- Each keymap: `vial` (Vial-enabled) and `default` (standard QMK)

## Firmware Storage

### In Repository

Built firmware files for the Vial keymap are automatically stored in:
```
keyboards/keychron/k2_pro/ansi/rgb/firmware/
keyboards/keychron/k3_pro/ansi/rgb/firmware/
keyboards/keychron/q8_pro/ansi_encoder/firmware/
```

Each directory contains:
- `README.md` - Instructions for building and flashing
- `*.bin` files - Pre-built firmware (generated by CI)

### As GitHub Releases

When you create a git tag (e.g., `v1.0.0`), the pipeline will:

1. Build firmware for all keyboards
2. Create a GitHub Release
3. Attach all Vial keymap `.bin` files to the release
4. Include release notes with features and installation instructions

## Manual Building

If you want to build locally instead of using CI:

```bash
# Install dependencies (first time only)
python3 -m pip install --user qmk
qmk setup

# Build firmware
make keychron/k2_pro/ansi/rgb:vial
make keychron/k3_pro/ansi/rgb:vial
make keychron/q8_pro/ansi_encoder:vial
```

Built firmware will be in `.build/` directory.

## Creating a Release

To create a new release with firmware:

```bash
# Tag the commit
git tag -a v1.0.0 -m "Release v1.0.0 - Initial Keychron support"

# Push the tag
git push origin v1.0.0
```

The CI pipeline will automatically:
1. Build all firmware
2. Create a GitHub Release
3. Upload firmware files
4. Add release notes

## Flashing Firmware

### Using QMK Toolbox (GUI)

1. Download QMK Toolbox from https://github.com/qmk/qmk_toolbox/releases
2. Download the appropriate `.bin` file from the [Releases page](https://github.com/joeybuddy/vial-qmk/releases)
3. Open QMK Toolbox
4. Select the downloaded `.bin` file
5. Put your keyboard in bootloader mode:
   - Press and hold `Fn + Esc` while plugging in USB cable, OR
   - Press the reset button on the back of the keyboard
6. Click "Flash" in QMK Toolbox

### Using Command Line

```bash
# Flash directly from repository
qmk flash -kb keychron/k2_pro/ansi/rgb -km vial

# Or flash a specific file
qmk flash keychron_k2_pro_ansi_rgb_vial.bin
```

## Features in Vial Builds

All Vial keymap builds include:

✅ Full USB (cable) connectivity  
✅ Full Bluetooth connectivity with multi-host pairing (3 devices)  
✅ Vial support for easy keymap customization  
✅ Battery management and level indication  
✅ Power saving features  
✅ Custom keycodes:
  - `BT_HST1`, `BT_HST2`, `BT_HST3` - Switch between paired Bluetooth devices
  - `BAT_LVL` - Display battery level
✅ Mac/Windows shortcuts built-in

## Technical Notes

### EEPROM Optimization

Due to STM32L432 EEPROM constraints on wireless keyboards:
- VIALRGB is disabled (RGB works, just not per-key configurable)
- Layer count limited to 2 by default
- Macros, tap dance, and combo features disabled
- LTO enabled for firmware size optimization

Users can adjust these settings in `keymaps/vial/config.h` if needed.

### Bluetooth Features

All keyboards support:
- 3-device multi-host pairing
- Battery level monitoring
- Power saving modes (LPM)
- RTC-based timers
- HID report buffering

## Troubleshooting

### Build Fails

Check the GitHub Actions logs for detailed error messages. Common issues:
- EEPROM size exceeded - Reduce features in `config.h`
- Missing dependencies - Ensure submodules are initialized
- API changes - Update compatibility layer if needed

### Flashing Fails

- Ensure keyboard is in bootloader mode
- Try a different USB cable or port
- Check that you're using the correct firmware file for your keyboard model
